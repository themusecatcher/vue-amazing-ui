全局化配置 ConfigProvider ​

赞助

为组件提供统一的全局化配置

本页提供可交互示例与 API 参考；概念、派生规则、变量清单与排查见定制主题。

何时使用 ​

  • 想统一换掉整套配色（品牌色、成功 / 警告 / 错误色、明暗模式）
  • 只想让页面的某一块区域换肤，而不是整页
  • 需要给弹窗 / 消息这类「不在组件树里」的浮层单独配主题

配置面：从全局到实例 ​

自上而下，作用范围依次收窄，冲突时按普通 CSS 级联处理。

改动目标配置入口生效范围
品牌色 / 成功·警告·错误色 / 中性基调theme.seed整页或整个子树
浅色 / 暗色 / 跟随系统theme.mode整页或整个子树
某个组件的整套主色（如「按钮要绿色」）theme.components.<组件>.primaryColor该组件的全部状态
某个组件的某个细节（如「滑块手柄的光环」）--va-<组件>-* 组件令牌单个视觉面
单个实例组件 prop（如 Button.color）或 style该实例

这几层的优先级、CSS 继承关系与「颜色没生效」的排查顺序，见定制主题：优先级链。下面按「从大到小」逐层演示。

种子换色：全组件联动 ​

只修改种子 seed.primary 一个值，所有消费主色的组件同步换色，无需逐组件传色。


修改主题色，以下组件配色实时联动
primaryColor:
#ff6900
--va-primary-color--va-primary-color-hover--va-primary-color-active--va-primary-bg-color--va-primary-border-color--va-link-color

色块取自当前作用域实际写入的变量值，而非静态示例色。修改种子后仅重算 15 个变量：主色 6（含上排 5 个色块与主色文字）、info 3、链接 3（末位色块，基色取 info，本节未单独设置故与主色同值）、焦点环 1、深色皮肤底色 2（只被 Menu 的 theme="dark" 消费，故不单独占色块）。其余 27 个值不变。

  • 色块与下方组件读取同一组 CSS 变量：二者位于同一 Provider 作用域，不存在第二份色值，因此始终同步；
  • 示例覆盖全部 39 个消费主色的组件；Table 排序箭头、Badge 计数底、Timeline 的 blue 圆点、GradientText 渐变端点均取自种子（点击 Table 表头可见）；
  • Tag 的 processing 预设取主色，success / warning / error 取语义色（见「语义种子」一节）；其余 13 个命名色为组件自有色板，与种子无关；
  • 深色皮肤（如 Menu 的 theme="dark"）底色取种子派生的品牌色暗底：改主色时根列表、浮层面板与内联子菜单一起换；
  • Message / Modal / Notification 在本节用组件形态（<Message @ready> 等）取实例：弹层渲染在本作用域内，换主色时一起变色，useXxx() 命中的是入口的全局实例，只跟随页面级主题；
  • 组件样式只消费 var(--va-*)，不参与换色计算：切换种子不会重建组件，也不会触发重渲染。

两种方式都不会改写 <html>，dispose() 也不会误清除主应用写入的变量。

浮层层级：baseZIndex ​

浮层层级需同时满足两点：弹窗内的下拉、提示不被遮罩覆盖；多个弹窗并存时，后打开者位于上层。组件自带默认层级，也可传 baseZIndex 交由 Provider 统一分配。

各组件默认层级 ​


浮层按类型划分层级：锚点跟随型浮层（Tooltip / Select 等）需高于承载它的视口固定型浮层（Modal / Drawer / Dialog），否则会被遮罩盖住：

浮层默认层级说明
Tooltip（含 Popover / Popconfirm / Ellipsis / Rate / BackTop / FloatButton 的气泡）1070锚点跟随型需高于 Modal / Drawer / Dialog
Select / AutoComplete / Dropdown / DatePicker / TimePicker / ColorPicker（含 Cascader / Pagination / Calendar 的下拉）1050同上
Modal / Dialog1000（遮罩）/ 1010（弹窗）弹窗在遮罩之上 +10
Drawer1000遮罩在容器内按 DOM 顺序排列
Image 全屏预览1070（遮罩）/ 1080（预览）/ 1081（操作按钮）预览高于 Modal / Drawer
Message / Notification1030 / 1040全局反馈层：高于承载层（Modal 弹窗 1010）、低于锚点跟随型浮层（Select 1050 / Tooltip 1070）
LoadingBar9999始终在最上层
BackTop9（可配 zIndex）页面级控件，需低于浮层，不参与自动分配
FloatButton99（可配 zIndex）同上
Spin 局部遮罩9相对自身容器的局部层级，不参与全局分配
Badge / Watermark 装饰层9 / 90（可配 zIndex）装饰性叠加，不参与全局分配

上表的取值遵循「基准 1000 + 类别偏移」的规则（Tooltip / Image +70、Select +50、Message +30、Notification +40）：同类浮层共用同一偏移量；同一层内部再按 10 为步长细分（如 Modal / Dialog 的遮罩 1000 / 弹窗 1010，Image 的遮罩 1070 / 预览 1080）。BackTop（9）与 FloatButton（99）为页面级控件，不参与该序列。


反馈层刻意不占据最高层级 —— 这样在消息 / 通知内容里放 Select / Tooltip 时，浮层不会被消息框压住。取值 1030 / 1040 是为了与 Modal 弹窗（1010）、Select 面板（1050）都不打平：同层级时上下关系会退化为 DOM 顺序（模板源码顺序），顺序不可控。LoadingBar（9999）始终保持最上。

自动分配（可选） ​


传入 baseZIndex 后，ConfigProvider 会向下注入层级分配器，锚点跟随型与视口固定型浮层共同消费：

  • 浮层在出现时领取层级，分配点恒在当前所有已打开浮层之上，即「后出现者在上」—— 该序列只用于没有承载关系的独立浮层之间（多个弹窗、多个页面级下拉）；
  • 浮层位于承载层（Modal / Drawer / Dialog / 上层浮层面板）内时，会挂进该承载层的内容容器，层叠关系由 CSS 的包含关系表达 —— 因此它恒在其承载层之上、随承载层一起显隐与位移，不受层级序列影响；未处于任何承载层内时仍挂 body；
  • 层级数值随「同时可见的浮层数」增长，不随打开次数无限增大（浮层隐藏后即归还层级）；
  • 承载层关闭时，其内部已打开的浮层（如 Select 下拉）会一并收起（收起即归还层级）；
  • 各组件自身的 zIndex prop 优先级最高；
  • 不传 baseZIndex 时各组件使用上表的默认层级，可按需开启。

常见问题排查 ​

按「改的是哪一层」定位，再检查作用域与覆盖范围；完整清单见定制主题：排查清单。

  • 悬停 / 按下跳回默认色：只覆盖了常态，组件令牌要整组覆盖（常态 / 悬停 / 按下）；
  • 弹窗 / 下拉没跟随：确认在 ConfigProvider 子树内；页面级主题要在最外层用 abstract: true；
  • 暗色只变了一半：纯 CSS 切暗色时 data-va-mode 要写在实际作用域节点上；
  • 自定义 SVG 不变色：fill 是 presentation attribute，不解析 var()，请写进 style。

几条实践建议：

  • 应用根部只放一个 Provider：abstract: true + seed / mode，页面内需要局部换肤时再嵌套 abstract: false；
  • 不要用令牌重复配置同一个颜色：优先用 theme.components 让系统派生状态，令牌只用于细部件；
  • 在 JS / canvas / SVG 中取色：用主入口公开的 derive(seed, mode)，与 --va-* 逐值一致，不要自己拼色阶；
  • 品牌色偏浅时主动换深色：系统不替品牌色做对比度兜底，主色文字与白字对比度不足时应更换主色，或单独覆盖 --va-primary-text-color / --va-text-color-solid。
